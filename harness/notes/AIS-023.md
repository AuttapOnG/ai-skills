# AIS-023 — Retire cli-subagents (remove from registry)

**Status:** done (2026-08-10)

## What shipped
- `skills/cli-subagents/` removed (SKILL.md + `references/codex.md`, `references/gemini.md`).
- `registry.json` regenerated — **11 skills**.
- [`skills/orchestrate/SKILL.md`](../../skills/orchestrate/SKILL.md) "When NOT to use":
  the external-CLI bullet reworded to keep the rule (external delegation is out of this
  skill's scope) without naming a skill that no longer exists in the registry.

## Why retired
- The owner ended the cross-CLI delegation workflow this skill existed for.
- Gemini CLI is no longer installed on the owner's machine — half the skill's agent
  references were already dead in practice.
- Codex is now reachable via MCP from inside the coordinating runtime, which obsoletes the
  skill's hard-won raw-CLI mechanics (close stdin, background dispatch, stall watchdog,
  pgrep targeting).
- The remaining need — "pick the right model tier per task" — is already covered by
  `orchestrate` (AIS-020). Rewriting cli-subagents into a model-selection skill would have
  duplicated it, so removal was chosen over rewrite.

## Key decisions
- **Hard removal, not soft deprecation.** The registry has no deprecation convention and a
  single maintainer. Copies installed elsewhere keep working but stop receiving updates;
  the discover-new-skills flow (AIS-013) can no longer offer it.
- **Historical records untouched.** Specs, plans, and earlier notes (AIS-002/003/014/020)
  still mention cli-subagents — they describe what was true at the time.
- **Owner-side cleanup happened outside this repo:** the local install was removed and the
  personal runtime config's external-delegation trigger sentence was dropped, leaving
  `orchestrate` as the only delegation-economy skill.
