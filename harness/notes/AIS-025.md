# AIS-025 — init-harness: feature grouping + archive discipline

**Status:** done (2026-08-19)

## What shipped
- `skills/init-harness/SKILL.md` (Step 4 templates):
  - `feature_list.json` schema gains optional `group` per feature (key into a top-level
    `groups` map — short epic/phase/milestone name, each mapped to a one-line goal).
    Flat field by design: nesting groups around features would make agent edits
    error-prone and conflict with the existing merge rule (preserve entries/IDs, only
    append).
  - Archive discipline (harness/README.md template, rule 6): when every feature in a
    group is `done` AND the active list exceeds ~20 entries, move that group's entries
    to `harness/archive/feature_list.json` (same schema, append-only) and collapse the
    Feature-index rows into one line under **Archived groups** in `progress.md`. Note
    files never move — they are loaded per-feature so they cost nothing until opened,
    and moving them breaks links. Active list + archive = full record; IDs never reused.
  - `progress.md` template gains the optional **Archived groups** section.
- Dogfooded in this repo's own harness: `groups` = {v1, phase-4}; AIS-001→011 tagged
  `v1` and archived to `harness/archive/feature_list.json` (active list was 25 > ~20,
  now 14); AIS-012→025 tagged `phase-4`; harness/README.md documents the archive.
- Verified: 2× Haiku smoke tests — positive case changes exactly the three files and
  leaves notes untouched; negative case (8 active entries) correctly refuses to
  archive. Repo `init.sh` skill↔harness parity greps all of `harness/` recursively,
  so archived entries under `harness/archive/` still count as tracked.
